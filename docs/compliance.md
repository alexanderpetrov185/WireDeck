# RF Compliance Labeling (Sprint 19)

Механизм автоматической проверки текста поста перед публикацией в Telegram на
совпадения с watchlists (иноагенты / терроризм-экстремизм / нежелательные организации).

> **Юридический дисклеймер.** Это технический инструмент, а не юрконсалтинг.
> Оператор **сам** ведёт и актуализирует списки и формулировки обязательных сносок;
> система лишь гарантирует, что настроенное правило будет применено к каждому посту.
> Актуальные реестры ведут уполномоченные органы РФ — скрапинг закрытых реестров не реализован.

## Как это работает

1. Перед отправкой в Telegram итоговый текст поста сканируется на case-insensitive
   substring-совпадения с `terms` из конфига.
2. Политика задана в конфиге на категорию:
   - `label` — к посту добавляется обязательная сноска (конец поста, пустая строка-разделитель);
   - `block` — публикация отменяется (claim откатывается), новость остаётся APPROVED с меткой.
3. Найденные категории сохраняются в `news.compliance_labels` (видно в админке).
4. Совпадения логируются (`category`, `action`, `term` — без полного текста поста).

## Конфигурация

```bash
# .env (не обязательно — compose даёт дефолт /app/compliance.lists.json)
COMPLIANCE_LISTS_PATH=/app/compliance.lists.json
```

```yaml
# compose.yaml (backend volumes) — уже настроено; оператор подготавливает реальный файл:
#   cp compliance.lists.example.json compliance.lists.json   # затем отредактировать
volumes:
  - ./compliance.lists.json:/app/compliance.lists.json:ro
```

Формат — `compliance.lists.example.json` (фиктивные terms, реальные данные оператор вносит сам):

```json
{
  "foreign_agent": {
    "action": "label",
    "footnote": "Текст обязательной сноски.",
    "terms": ["Имя Отчество Фамилия", "Название организации"]
  },
  "terror_extremist": { "action": "block", "terms": ["..."] },
  "undesirable_org": { "action": "label", "footnote": "...", "terms": ["..."] }
}
```

- `action: label` — автопубликация разрешена, сноска обязательна.
- `action: block` — автопубликация запрещена, новость остаётся APPROVED с меткой для ручного разбора.
- Списки загружаются **при старте backend** — после обновления файла рестарт контейнера.

## Runbook обновления списков

1. Отредактируйте файл списков (актуализируйте по официальным реестрам).
2. `docker compose restart backend` (списки читаются при старте).
3. Проверьте лог: `Compliance labeling enabled: N category(ies), M term(s)`.

## Ограничения

- Substring-матчинг даёт false positives (однофамильцы) — block-новости разбирает оператор.
- Списки устаревают без обновлений — механизм не заменяет ответственность оператора.
- Link-preview в Telegram не сканируется (система проверяет только текст поста).
