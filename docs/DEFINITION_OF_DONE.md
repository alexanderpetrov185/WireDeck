# WireDeck — Definition of Done (DoD)

Документ фиксирует обязательные критерии завершения любой задачи/спринта в проекте WireDeck.

## Обязательные критерии

Каждая задача считается **выполненной** только если выполнены ВСЕ следующие критерии:

### 1. Lint

- [ ] `npm run lint` проходит без ошибок
- [ ] Ошибки ESLint отсутствуют в backend и frontend

### 2. Tests

- [ ] `npm test` проходит успешно
- [ ] Все тестовые suites (backend) проходят без failures
- [ ] Новый код покрыт тестами (если применимо)

### 3. Build

- [ ] `npm run build` проходит успешно
- [ ] Backend (NestJS) собирается без ошибок
- [ ] Frontend (Next.js) собирается без ошибок

### 4. Docker

- [ ] `docker compose build` проходит успешно
- [ ] Образы backend и frontend собираются без ошибок
- [ ] `docker compose up -d` запускает все сервисы
- [ ] Все контейнеры (postgres, redis, backend, frontend) находятся в статусе healthy/running

### 5. Health Endpoint

- [ ] `GET /health` возвращает HTTP 200
- [ ] Ответ содержит `"status": "ok"`
- [ ] База данных и внешние зависимости в статусе `up`

### 6. Documentation

- [ ] Документация обновлена (если изменения затрагивают архитектуру, модули, API)
- [ ] `docs/ARCHITECTURE.md` актуален
- [ ] `docs/ROADMAP.md` актуален (НЕ изменяется автоматически)
- [ ] `docs/MODULE_BOUNDARIES.md` актуален
- [ ] `docs/TECH_DEBT.md` обновлён (если выявлен новый технический долг)

### 7. Commit

- [ ] Изменения закоммичены с осмысленным сообщением
- [ ] Сообщение коммита следует конвенции (например, `feat:`, `fix:`, `refactor:`, `docs:`)

### 8. Push

- [ ] Изменения запушены в удалённый репозиторий
- [ ] Ветка `develop` синхронизирована с `origin/develop`

## Примечания

- Если какой-либо критерий не может быть выполнен (например, Docker недоступен),
  это должно быть явно задокументировано в результате задачи.
- Definition of Done применяется ко ВСЕМ задачам, включая документационные и рефакторинговые.
